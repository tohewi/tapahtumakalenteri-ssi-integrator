## Codebase Patterns
- **Module Boundaries (`scoring-proxy`)**:
  - Routes (`scoring-proxy/routes/*.js`) are thin HTTP dispatchers: validate input -> call service (`lib/services/*.js`) or domain module (`lib/ssi-core/*.js`) -> return JSON.
  - Domain modules in `scoring-proxy/lib/ssi-core/*.js` (`graphql.js`, `scoring.js`, `participants.js`, `management.js`) may import ONLY `http-helpers.js` (and `constants.js`/`../logger.js` where needed). Never import across domain modules or from `ssi-core/index.js`.
  - Services (`scoring-proxy/lib/services/*.js`) hold pure business logic and orchestration without Express `req`/`res`.
- **SSI GraphQL `SquadInterface` Inline Fragment Rule**:
  - In SSI GraphQL, `match.squads` is typed as `SquadInterface` (exposing only `id`, `number`, `comment`). Never query `competitors` or `max_competitors` directly on `squads` — always wrap them in `... on NordicSquadNode { max_competitors competitors { ... } }`.
- **Logging Discipline**:
  - Never use raw `console.log` / `console.warn` / `console.error` in `scoring-proxy/routes/*.js` or `scoring-proxy/middleware/*.js`. Always import `{ log } from '../lib/logger.js'`.
- **File Size Guideline**:
  - Keep backend routes/services and frontend React page components under ~500 lines. Extract sub-components into `scoring-ui/src/components/<feature>/` and business logic into `scoring-proxy/lib/services/`.
- **Agent Instructions Synchronization**:
  - Whenever `AGENTS.md` is updated with new patterns or file mappings, `.github/copilot-instructions.md` must be updated identically in the same commit.
