## 2. GraphQL-Based Operations (✅ Done)

| **Score read-back verification** | `ssiGraphQL` — scoring route | `competitor` query |

## 4. Hybrid Operations

### 4.1 Nordic RESUL Cup Builder (`nordic-cup-graphql-builder.js`)
Named "GraphQL builder" but currently uses **web form POST** for creation due to a confirmed GraphQL limitation.

| Step | Method | Reason |
|------|--------|--------|
| Fetch form HTML for defaults | Web scraping | Must extract `weapon_groups`, `categories`, `competence_classes` defaults from SSI form |
| Create RESUL cup | **Web form POST** | GraphQL `create_event` ignores multi-value array fields — they fall back to SSI defaults silently |
| Create component matches | **Web form POST** | Same multi-value field issue |
| Link matches to cup | Web scraping | No `add_component_event` mutation confirmed |
| Create squads | Web scraping | No `create_squad` mutation in SSI GraphQL |

**Note:** The file is named `*graphql-builder*` because the architecture was designed for GraphQL, and it should be the target once SSI fixes multi-value field handling in `create_event`. The builder is ready to switch — only the cup and match creation steps need to be replaced with `ssiCreateEvent` calls.

### 4.2 SRA Standalone Match Builder (`sra-graphql-builder.js`)
| Step | Method | Reason |
|------|--------|--------|
| Create SRA match | **GraphQL** (`create_event` mutation, rule=`sr`) | Works — SRA matches don't have the multi-value field problem |
| Create squads | Web scraping | No `create_squad` mutation |

## 5. Known SSI GraphQL Limitations

These are confirmed SSI-side restrictions that block further migration:

| Limitation | Impact | Workaround |
|------------|--------|------------|
| **`create_event` ignores multi-value fields** (`weapon_groups`, `categories`, `competence_classes`) | Cannot create Nordic cups/matches via GraphQL without losing discipline config | Web form POST for Nordic creation |
| **No `create_squad` mutation** | All squad creation is web scraping | None — no alternative API exists |
| **No participant write mutations** | Registration, approve, delete, squad assignment all require web scraping | None |
| **No component linking mutation** | Cup ↔ match linking requires web form | None |
| **No event deletion mutation** | Event deletion requires web form | None |
| **`shooter.email` returns `null` for IPSC/SRA** | Cannot use GraphQL for email-based participant identification in SRA events | Web scraping of participant detail page (available but not yet implemented for disambiguation) |
| **No staffing / group management mutations** | All management group operations are web scraping | None |
| **No paid/DNS status in GraphQL** | CUP management page status reads require scraping | None |

## 7. Risk Assessment

| Area | Risk | Severity | Note |
|------|------|----------|------|
| Nordic cup creation (web form) | SSI changes create-cup form structure | **Medium** | Form field parsing is generic (`parseFormFields`) — new fields are preserved automatically. Structural HTML changes would break it. |
| Participant registration (search-and-add) | SSI changes participant search UI | **High** | Multi-step flow, HTML-dependent. Breaking changes would fail registration silently if not monitored. |
| Score submission (form POST) | SSI changes scoring form | **Medium** | Verified 2026-02-06 — no CSRF. HTML-dependent. |
| Staffing (group management) | SSI changes staff management UI | **Medium** | Complex multi-step scraping, 200+ lines. |
| CUP toggle-status (approve/delete/DNS/paid) | SSI changes participant URLs | **Low** | Simple GET redirects, stable URL patterns. |
| SRA match creation (GraphQL) | SSI changes `create_event` mutation | **Low** | GraphQL schema is versioned and more stable than HTML. |
